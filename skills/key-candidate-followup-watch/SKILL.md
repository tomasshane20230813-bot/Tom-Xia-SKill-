## 谁算「重要进展」人选

猎头空间（xi-tou-gong-zuo-kong-jian）中满足任一条件的人：

- stage 为 interviewing / submitted / offered；
- 已约或已完成客户方（HR / HM）面试，在等下一步；
- 在等客户反馈、薪资方案或 offer，且没有确定的回音日期；
- 薪资谈判未落地（报价、期望、底线之间还有未决项）；
- 有竞争机会在并行推进，存在时间压力（对方出反馈日、对方先谈薪等）；
- 空间卡 nextFollowUp 写的下一步已到期或逾期，且没有结果记录。

## 什么时候触发

1. **每日晨间简报必带「重点人选」一节**：逐人一行，见下方格式。
2. **事件驱动即时提醒**：面试结束当天或次日仍无结果记录；客户承诺的反馈日到了没动静；竞争机会的时间窗临近（提前一天提醒）；追问类提醒到期而事项仍未闭环。
3. **连带扫描**：每次更新任何一位重点人选的进展（空间卡、人物档）时，顺手扫一遍全表，看其他人有没有到期未办的下一步。
4. **被问起时全表汇报**：Tom 问起任何一位人选时，顺带把重点名单的整体状态一并报清。

## 数据来源与核对

- 猎头空间 getoverview（stage / nextFollowUp / notes）；
- 人物档 ~/memory/people/<person>.md（以此为准，空间数据不自动同步）；
- 日历上已设的追问/面试提醒、Gmail 重要来信看守的信号。
- 来源冲突时先核对再报；没记录的结果只写「待反馈 / 待 Tom 补记」，绝不猜测或编造面试结果。

## 提醒格式

一人一行，五要素齐全：

**名字 — 当前步点 — 在等什么/等谁 — 已拖时长或截止点 — 建议 Tom 的下一步动作**

- 只报需要 Tom 本人动作或决策的事项；纯等待且未到时点的，晨报里带一句即可，不单独打扰。
- 同一事项在一个决策点只提醒一次；逾期、竞争方推进等情况恶化时才升级再提醒。
- Tom 已明确决定的事项（如「先不发」）不反复翻出来。

## 红线

- 只提醒 Tom 本人；绝不替 Tom 联系人选或客户，绝不代发任何跟进消息。
- 对外发消息、删东西、改 Tom 的文件，仍须先经他批准（本 skill 不改变这条）。
- 提醒走主聊天 + WhatsApp 双通道（按现行通知路由）；WhatsApp 未重连期间以主聊天为准。
