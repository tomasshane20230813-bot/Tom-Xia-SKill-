# 人选进展反馈四处同步（Candidate Progress Sync）

- Tom 2026-11-19 下达的长期要求：他给的每一条人选反馈（面试结果、通过/淘汰、Pending、改期、谈薪进展等），Muse 都要自己判断是否需要备注，并自动同步到下面四处，不等他逐处交代。
- 本 skill 长期生效、随时调用执行；同步存于 GitHub 仓库 tomasshane20230813-bot/Tom-Xia-SKill- 的 skills/candidate-progress-sync/。

## 触发

- Tom 在聊天里给出任何人选的进展反馈（口头转述、截图、转发消息都算）；
- 或 Muse 从邮件、日历、看守等渠道确认到人选进展变化。

## 同步四处（缺一不可）

1. **猎头空间人选卡**：stage、nextFollowUp、notes 追加条目，按五要素写全：当前阶段、在等什么、下一步动作与时点（外加关键事实，如面试官评价、薪资口径）。
2. **Notion 对应人选表该人选行**：Recruiter Notes 追加同样的进展；状态字段（Status）随阶段更新。
3. **人物档** ~/memory/people/<person>.md：追加带日期的进展条目。
4. **Ongoing Process 人选汇总**：Notion「2026年11月计划」页 + 最新周五复盘页 + 猎头空间留底模板（模板 id 9；空间开头 Headline 区读的就是它）。

## Ongoing 条目维护

- 人选进入重要进展（过初面 / 进下一轮 / 面试已定 / 谈薪 / offer / Pending）→ 加入或更新对应客户条目；被淘汰 / 关闭 / 婉拒 → 从「现推进」里删掉或明确改注已淘汰。
- **条头框架句必须与括号内现状一致**：人数、阶段、「目前无人」之类的结论句，每次同步时顺手核对；框架与事实冲突，立刻改框架，不许留着旧汇总句误导。（教训 2026-11-19：DeepCtrls 条头写「推荐1人被HR淘汰，目前无人」，实际 Kelvin Ong 还在推进、面试已定 11-24，被 Tom 当场骂醒；同批还修正了印度销售条头人数与澳洲条头的过期前提。）
- 括号内细节按五要素写全，只写名字不算记录。

## 纪律

- 相邻消息涉及不同人选：逐人分开处理、逐人一行汇报，绝不混为一谈。
- 同步完逐处读回核验（Notion fetch 读回、空间 getoverview 核对）再报完成。
- 没记录到的事实写「待确认 / 待 Tom 补记」，绝不编造面试结果或反馈。
- 本 skill 只管记录同步；对外发消息、删东西、改 Tom 的其他文件，仍按原规矩先经他批准。
