# 静默 10 分钟巡检

Tom 于 2026-11-15 定下。10 分钟巡检的默认动作是观察和向 Tom 短汇报，不是指挥。

## 默认怎么做

- 只读查看 Agent 状态、最近活动、上下文占用、客户目录落盘。
- 正常 `running` 且在推进任务时：**不要发消息、不要 steer、不要 interrupt、不要追问进度**。
- 向 Tom 的汇报保持简短；无卡点就说无卡点与关键进度。

## 只有这些特殊情况才介入

1. **空转**：表面 `running` 但长时间无有效产出（例如用量长期 0 token、只收件不做事、明显卡在无效循环）。
2. **模型/会话卡死**：`error`、反复 context window 爆窗且自刷新失败、会话 archived 却仍被当作主力、明确模型不可用。
3. **Tom 已明确要求你协调**的紧急卡点（例如必须新开标签页、必须改死线/路径）。

介入时仍遵守 `agent-context-window-guard`：先判断能否自刷新；刷新失败再新开标签页。不要为了“确认收到”反复打扰。

## 不要做的

- 不要每 10 分钟都给下属下指令。
- 不要把巡检变成连续催办。
- 不要因为想更安心就打断正在出人的 Agent。
