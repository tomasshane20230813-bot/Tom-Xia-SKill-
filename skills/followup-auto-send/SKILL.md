# 跟进邮件自动发送（Follow-up Auto Send）

- Tom 2026-11-24 下达的自动化工作流：凡是已经录入猎头空间、**有邮箱、且首封外联邮件已经发出**的人选，未回复的，由 Muse **自动**按节奏发跟进 #2、#3，不再等 Tom 逐批点名、不再逐封问他。
- 本 skill 只管「什么时候自动发、发给谁」的触发与调度；模板、串联方式、编码与核验纪律全部按 skill `followup-email-system` 执行，两者叠加适用。
- 长期生效；同步存于 GitHub 仓库 tomasshane20230813-bot/Tom-Xia-SKill- 的 skills/followup-auto-send/。

## 节奏（2026-11-24 定版：每隔 2 天；2026-11-26 Tom 改为按工作日算）

- **每隔 2 个工作日一封**：跟进 #2 = 首封发送日起算第 2 个工作日；跟进 #3 = 跟进 #2 发送日起算第 2 个工作日（即首封起算第 4 个工作日）。没有 #4。
- **工作日 = 周一至周五（北京时间），周六周日不算**：到期日落在周六或周日时，自动顺延到下一个工作日。到期日永远不会落在周末。
- 算例（自首封发送日起数，周末跳过）：
  - 首封周四 → #2 下周一（周五算第 1 个、周一算第 2 个），#3 下周三（周二第 1 个、周三第 2 个）。
  - 首封周五 → #2 下周二（周一第 1 个、周二第 2 个）。
  - 首封周三 → #2 周五（周四第 1 个、周五第 2 个）。
- 此节奏覆盖一切旧口径（followup-email-system 原 T+3/T+7、以及 2026-11-24 上午短暂用过的每 3 天）；已排期的按新规顺延为准。
- 已回复者一律不发（发送前必须查收件箱）；婉拒者走 decline 固定回复，不进本节奏。

## 自动调度

- cron `followup-auto-send-daily` 每天约 09:30（北京时间）扫一轮（周末也跑，但到期日永远不会落在周末，所以周末无发送）：
  1. 读猎头空间候选人（stage=contacted），结合人物档与 Gmail 已发送，算出每人的首封日、已发跟进数、下一封到期日。
  2. 到期且无回信的，按 followup-email-system 构建 .eml（threaded 回首封、真实 Message-ID、Subject 含非 ASCII 时 RFC 2047、单独薪资带的人靠 Re: Subject 与首封一致自动沿用），逐封顺序发、间隔随机 3–7 分钟、逐封从已发送核验。
  3. 发完更新人物档与空间卡的 nextFollowUp（一行总账：谁、第几封、已核验）；#3 发完写明「跟进已完结，无 #4」。
  4. 有发送或有阻塞才向主聊天汇报；无人到期则静默。
- 发送若被审批卡挡下：记成待审批清单汇报 Tom，绝不静默、绝不绕过。

## 数据来源与判定

- 「已发首封」以 Gmail 已发送为准，不凭记忆；「无回信」以发送前查该人邮箱的收件箱记录为准。
- 空间卡的 nextFollowUp 与人物档的跟进记录是排期依据；两者冲突时以 Gmail 实际发送记录为准并当场修正记录。
- 无邮箱的人选不进本流程（空间 stage=new 的多为此类），由 Tom 自行用 WhatsApp/LinkedIn 联系。

## 与其他规则的关系

- 新人选录入时卡上写准首封日与跟进到期日（见 candidate-intake-sync），本流程才有据可依。
- Tom 当批另有指示（如某人先不发、某批作罢）时从其指示，并在记录里写明。
