# 已连接招聘插件主动协同

Tom 于 2026-11-15 要求：Codex 中已经连接的 LinkedIn、Apollo、SignalHire 及同类插件，该用都要用。此规则适用于人才寻访、职业履历读取、职责补证、公开档案链接核验及招聘数据交叉检查。

## 执行口径

- 每轮开始盘点当前可调用的相关插件；使用工具发现接口搜索名称和能力。已连接不等于本会话可调用，搜索无结果不能声称插件不存在或已执行。
- 将插件用于具体缺口：找新人、确认现职与地点、读取职责、核对学历和任职时间线、验证个人档案链接。所有与当前缺口相关、可用且在授权范围内的插件都应主动使用，不等 Tom 逐个点名。
- 一家来源只有职称或空职责时，立即换能读完整履历的来源；不能因公开 LinkedIn 遇到登录墙就停止补证。已有充分证据时，不为凑调用次数重复查询同一字段。
- 独立查询可并行；依赖搜索结果、任务 ID 或异步富化状态的步骤顺序执行。工具不可用时，向具备该工具的协作 Agent 请求代查，说明具体人选、字段及限制。

## 按能力路由

以下为常见插件示例；实际工具名称、参数与返回字段以当前连接器说明为准，不把这张表当固定白名单。

| 插件 | 优先用途 |
| --- | --- |
| LinkedIn | 个人职业档案发现、姓名与公司消歧、真实个人 URL |
| Apollo | 人才搜索、现职和职业经历补充；自然语言检索使用其 Agent，确定的结构化过滤使用对应搜索工具 |
| SignalHire | 人才搜索及完整职业履历；要求不取联系方式时使用无联系方式工具 |
| Clay | 定向找人、Summarize Work History、具体职业信息研究；异步任务必须读取实际结果与状态 |
| Lusha、FullEnrich | 职业档案预览、现职、地点及支持的任职描述 |
| Vibe / ai_vibe_prospecting | 按画像匹配、职业履历富化、读取样本与实际输出 |
| ZoomInfo | 找人、职业档案 URL、任职史、学历及有来源的职责字段 |
| DataForB2B | 结构化搜人、仅职业档案富化、公开职业活动 |
| RocketReach | 职业属性搜索、消歧及适用的职业资料模式 |
| The Org | 公司内职位、组织关系及档案链接交叉核对 |

新连接的同类插件同样纳入盘点。缺职责时优先调用能返回职责的功能，避免误用仅提供邮箱电话的富化接口。

## 失败处理与证据

- 401/403、402、429、字段缺失、任务未完成分别记录为权限、余额、限流、字段缺口或进行中，不能解释成市场无人。
- 参数错误按工具文档修正后做一次有针对性的重试；余额不足和限流按返回要求停止重打，换来源。换模型或换会话要继承本轮已确认的阻塞记录。
- 对关键结论记录来源、查询时间、个人 URL 或记录 ID、可见原文与证据级别；不同来源冲突时保留差异并标待核实。
- 公司、职位、地点不自动证明职责、个人业绩或语言等级。仅有职称不能虚构职责；缺毕业年不能用工作年反推毕业年。
- 对照已知历史库和排除名单查重，说明实际覆盖范围；只查了快照不能声称四端已经全量核验。
- 汇报简洁列出“成功、空结果、受阻、尚未调用”的来源及剩余缺口，不伪造调用、命中或联合核验。

## 授权与交付

- 使用插件不意味着解锁联系人、消费新付费额度、外联或写入 CRM 已获授权；遵守当前任务明确的字段限制和各工具实际确认要求。
- Tom 要求只读职业资料或不取邮箱电话时，选择无联系方式模式并关闭相关富化字段；工具只能返回联系方式且无法关闭时跳过并说明。
- 不登录 Tom 个人 LinkedIn，不使用个人 Chrome 或个人 cookies。
- 姓名门按 Tom 已定口径，优先于泛化禁令：任务要求华人时，领英姓名看起来像华人姓或中文拼音组合即通过（`chinese-name-by-appearance`），不要求汉字，不要求语言栏中文。任务要求男性时，用常见男性名侧面判断；明显女性名不进入该池；中性名标待核，不编造。
- 不从姓名或照片推断国籍、公民/PR、年龄或语言等级。语言只认语言栏或正文原文。职业是否合适仍看职称和职责。
- 人选初稿及时写入 Tom 指定客户目录；审查意见与工具日志留在对话或过程目录。公开 GitHub Skill 仅保存通用流程，不发布候选人资料、客户私密信息或凭据。
